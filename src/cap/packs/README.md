# radio packs / паки

Эта папка — **plug-and-play** для паков (именованных наборов настроек радио),
по образцу `src/cap/methods/`.

Методика (`src/cap/methods/`) — это **что** делать (алгоритм kick/probe).
Пак — это **какую методику выбрать + с какой интенсивностью** (готовый
набор ручек: `BIDIR`, `EAPOL TX`, `KICK N`, `PAUSE MS`, `LOCK MS`, `HOP MS`
и т.д.).

Чтобы добавить новый пак — **просто создай тут один `.cpp` файл**.
Ничего больше править не нужно: ни `config.cpp`, ни `settings_menu.cpp`,
ни `display.cpp`, ни `platformio.ini`.

---

## Минимальный шаблон

```cpp
#include "pack_ctx.h"

namespace Cap {
namespace Packs {

// TAG — уникальный C-идентификатор (для макроса), не обязан совпадать с NAME.
// NAME — то, что покажется в меню PACK и в нижнем баре (4..8 символов).
// METHOD_NAME — имя методики из src/cap/methods/ (см. CAP_METHOD_REGISTER
//   там), которую этот пак включит, или nullptr чтобы оставить AUTO.
// Preset{...} — какие ручки радио выставить; поля не заданные явно
//   остаются на безопасных дефолтах (см. Preset в pack_ctx.h).
// Полный список: bidir/eapol/pmkid/csa/auth + kick/pause/lock/hop
// + jitter/cooldown/scoreThr/hsDepth/dataAct/strictLock/depthHold.
static const Cap::Packs::Preset kMyPreset{
    /* bidirKick     */ true,
    /* eapolTx       */ false,
    /* pmkidProbe    */ false,
    /* csaHerd       */ false,
    /* authFlood     */ false,
    /* kickBurst     */ 4,
    /* pauseMs       */ 900,
    /* lockMs        */ 8000,
    /* hopMs         */ 300,
    /* jitterMs      */ 2,
    /* cooldownSec   */ 0,
    /* scoreThr      */ 0,
    /* hsDepth       */ 0,
    /* dataAct       */ 0,
    /* strictLock    */ true,
    /* depthHoldSec  */ 0,
};
CAP_PACK_REGISTER(mypack, "MYPACK", "ALL", kMyPreset)

} // namespace Packs
} // namespace Cap
```

## Что обязательно

1. **Файл лежит в этой папке** (`src/cap/packs/`) — PlatformIO сам его подхватит.
2. **`#include "pack_ctx.h"`** — даёт `Preset`, `Entry`, макрос регистрации.
3. **`CAP_PACK_REGISTER(TAG, "NAME", METHOD_NAME, PRESET)`** в namespace
   `Cap::Packs`, в самом конце файла. Без `;` в конце — макрос сам её ставит.
4. **`TAG`** — просто уникальный идентификатор среди всех `pack_*.cpp`
   (используется только чтобы собрать уникальное имя статической
   переменной), например имя файла без `pack_`/`.cpp`.
5. **`NAME`** — 4..8 символов, ASCII. Показывается в UI и в нижнем баре как есть.
6. **`METHOD_NAME`** — строка с именем методики (как в её `CAP_METHOD_REGISTER`),
   например `"OURS"`, `"PAN"`, `"PMKIDONLY"`. Если строка не найдена в таблице
   методик — пак тихо откатится на `AUTO` (безопасный fallback), но лучше
   передавай `nullptr`, если и правда хочешь `AUTO`.
7. **`Preset{...}` в отдельных `(...)`**, если пишешь его в несколько строк —
   препроцессор при разборе аргументов макроса следит только за вложенностью
   круглых скобок, а не фигурных, так что запятые внутри незащищённого
   `Preset{...}` разъедут его на "лишние" аргументы макроса. Смотри пример
   выше — вся фигурная инициализация обёрнута в `(...)`.

## Что нельзя

- ❌ Использовать то же `NAME` в двух файлах — таблица оставит последний
  (по линк-ордеру), но для предсказуемости давай уникальные имена.
- ❌ Использовать тот же `TAG`, что уже занят другим `pack_*.cpp` — не
  скомпилируется (конфликт имён статической переменной).

## Что будет после добавления

- Пак появится в меню **Radio → PACK** автоматически, между `STOCK` и `CUSTOM`.
- Появится в нижнем баре как `P:<NAME>`, когда выбран.
- Выбор пака сразу применяет его методику + все ручки из `Preset`.
- Как только юзер вручную покрутит любую ручку радио (`BIDIR`, `KICK N`...) —
  `PACK` переключится на `CUSTOM`, и твой пак больше не будет его перезаписывать,
  пока юзер сам не выберет пак заново.

## STOCK и CUSTOM

`STOCK` (все дефолты, методика = `AUTO`) и `CUSTOM` (сохранить ручные
настройки юзера) — это два встроенных, **не регистрируемых** слота.
Они не лежат в этой папке и не могут быть переопределены новым `pack_*.cpp` —
их обрабатывает напрямую `Config::applyRadioPack()`.

## Что уже есть из коробки

| Пак        | Методика   | Философия                                                                 |
|------------|------------|---------------------------------------------------------------------------|
| `STOCK`    | `AUTO`     | Дефолт — спокойные настройки, AUTO-ротация по таймеру                      |
| `OURS`     | `OURS`     | Broadcast kick, никаких трюков. Самый тихий и предсказуемый                 |
| `PAN`      | `PAN`      | Bidir + EAPOL-Start/Logoff + PMKID probe. Сбалансированный                  |
| `WOLF`     | `PAN`      | PAN + CSA-herd + auth-flood. Агрессивный                                    |
| `PORKCHOP` | `PORK`     | Porkchop-style: scoring одной цели, EMA по RSSI/клиентам, бир-бир jitter  |
| `STEALTH`  | `PORK`     | Только PMKID probe, ноль deauth. Тихий сбор, как DONOHAM                    |
| `AGGRO`    | `PORK`     | Всё вкл + CSA + auth-flood + 5-frame bursts. Самый громкий                  |
| `CUSTOM`   | (текущая)  | Взводится автоматически когда юзер крутит ручки вручную                     |

В меню **RADIO → PACK** пак идёт в порядке: `STOCK` → пользовательские (по
имени файла) → `CUSTOM`.
